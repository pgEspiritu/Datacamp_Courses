# 🧩 Subqueries Everywhere! & SQL Best Practices

## 🎯 Lesson Objective

Now that we have covered subqueries in:

- `SELECT`
- `FROM`
- `WHERE`

we can combine them in a single query.

SQL allows multiple subqueries, but as queries become more complex, **readability, formatting, indentation, comments, and proper filtering become increasingly important**.

---

# 1. 🧠 Subqueries Everywhere!

Subqueries can be used in multiple clauses within the same query.

For example, one query can contain:

- A subquery in `SELECT`
- A subquery in `FROM`
- A subquery in `WHERE`

Conceptually:

    SELECT
        column,
        (
            SELECT ...
        ) AS summary

    FROM
        (
            SELECT ...
            FROM ...
        ) AS subquery

    WHERE column IN
        (
            SELECT ...
            FROM ...
        );

There is no fixed rule that says you can only use one subquery.

---

# 2. 🔢 As Many Subqueries as You Need

SQL allows you to include multiple subqueries within a query.

However:

> ⚠️ More subqueries can make a query longer and harder to understand.

A complex query might contain:

    Main Query
        │
        ├── SELECT subquery
        │
        ├── FROM subquery
        │
        └── WHERE subquery

The goal is not simply to use as many subqueries as possible.

The goal is to use them **when they are useful and necessary**.

---

# 3. 📐 Format Your Queries

One of the best SQL habits to develop early is **proper formatting**.

Make sure major SQL clauses are clearly separated:

    SELECT
        ...

    FROM
        ...

    LEFT JOIN
        ...

    WHERE
        ...

    GROUP BY
        ...

    ORDER BY
        ...

    LIMIT ...;

This makes the query easier to read and maintain.

---

# 4. ✨ Why Formatting Matters

Consider this difficult-to-read query:

    SELECT name,AVG(home_goal+away_goal) FROM league l LEFT JOIN match m ON l.country_id=m.country_id WHERE season='2013/2014' GROUP BY name;

The same query is much easier to understand when formatted:

    SELECT
        l.name AS league,
        AVG(m.home_goal + m.away_goal) AS avg_goals
    FROM league AS l
    LEFT JOIN match AS m
        ON l.country_id = m.country_id
    WHERE season = '2013/2014'
    GROUP BY l.name;

Good formatting makes it easier to identify:

- What is being selected
- Which tables are being used
- How tables are joined
- Which rows are filtered
- How results are grouped

---

# 5. 📝 Annotate Your Queries

Use comments to explain what different parts of your query do.

Comments are especially useful when working with:

- Long queries
- Complex calculations
- Multiple subqueries
- Complicated `CASE` statements
- Queries that will be reused later

---

# 6. 💬 Multi-Line Comments

SQL supports multi-line comments using:

    /*
        This is a multi-line comment.
        It can contain multiple lines.
    */

Example:

    /*
        Calculate the average goals
        for the 2013/2014 season.
    */
    SELECT AVG(home_goal + away_goal)
    FROM match
    WHERE season = '2013/2014';

Everything between:

    /*

and:

    */

is treated as a comment.

---

# 7. 💬 Inline Comments

You can also use two dashes:

    --

Everything after `--` on that line is treated as a comment.

Example:

    SELECT
        name AS league,

        -- Calculate the league average
        AVG(home_goal + away_goal) AS avg_goals

    FROM league;

Comments can also explain filters:

    WHERE season = '2013/2014' -- Only use the 2013/2014 season

---

# 8. ⚠️ SQL Commands Inside Comments Are Ignored

For example:

    SELECT
        name,

        -- WHERE season = '2013/2014'

        AVG(home_goal + away_goal) AS avg_goals
    FROM league;

The `WHERE` inside the comment is treated as text and does not execute.

This can be useful when temporarily disabling part of a query.

---

# 9. 📏 Indent Your Subqueries

Always properly indent information inside a subquery.

Example:

    SELECT
        date,
        home_goal,
        away_goal
    FROM
        (
            SELECT
                date,
                home_goal,
                away_goal,
                home_goal + away_goal AS total_goals
            FROM match
            WHERE season = '2013/2014'
        ) AS subquery;

Notice that the subquery is visually separated from the main query.

This makes it easier to identify:

    Main query
        ↓
    FROM subquery
        ↓
    Inner query

---

# 10. 🧠 Why Indentation Helps

Proper indentation makes it easier to understand:

- Which query runs where
- Which conditions belong to which query
- Where filters are applied
- What information is being processed first
- What columns are generated by a subquery
- Where to make changes later

For example, if you need to change the season from:

    '2013/2014'

to:

    '2014/2015'

good formatting makes it easier to find every place where the filter needs to be changed.

---

# 11. 📦 Indent Complex SELECT Columns

Long expressions should also be formatted clearly.

This is especially important for:

- `CASE` statements
- SELECT subqueries
- Mathematical calculations
- Nested functions

For example:

    SELECT
        name AS league,

        ROUND(
            AVG(m.home_goal + m.away_goal)
            -
            (
                SELECT AVG(home_goal + away_goal)
                FROM match
                WHERE season = '2013/2014'
            ),
            2
        ) AS diff

    FROM league AS l
    LEFT JOIN match AS m
        ON l.country_id = m.country_id
    WHERE season = '2013/2014'
    GROUP BY name;

The indentation shows how the calculation is structured.

---

# 12. 🔀 Indenting CASE Statements

Long `CASE` statements should also be formatted.

Example:

    CASE
        WHEN home_goal > away_goal
            THEN 'Home Win'

        WHEN home_goal < away_goal
            THEN 'Away Win'

        ELSE 'Tie'
    END AS result

For more complex conditions:

    CASE
        WHEN home_goal > away_goal
             AND home_goal >= 3
            THEN 'High-scoring Home Win'

        WHEN home_goal < away_goal
             AND away_goal >= 3
            THEN 'High-scoring Away Win'

        ELSE 'Other'
    END AS result

Each condition is easier to follow when properly aligned.

# 14. ⚙️ Is That Subquery Necessary?

Not every problem requires a subquery.

Every additional subquery can require additional processing.

Depending on:

- Database size
- Number of rows
- Complexity of the query
- Number of subqueries
- Amount of data being processed

a complicated query may take longer to execute.

Therefore, ask yourself:

> **Do I actually need this subquery?**

---

# 15. 🧠 Think Before Adding a Subquery

Before using a subquery, consider whether the same result can be achieved more simply using:

- A `JOIN`
- `GROUP BY`
- An aggregate function
- A `CASE` statement
- A simpler filter

The goal is:

    Correct result
          +
    Clear query
          +
    Reasonable performance

---

# 16. ⚠️ Properly Filter Each Subquery

This is one of the most important concepts when working with multiple subqueries.

Each query operates independently.

Therefore, a filter in the main query does **not automatically filter a subquery**.

Likewise, a filter in one subquery does not automatically filter another subquery.

---

# 17. 📅 Example: Filtering 2013/2014

Suppose a query contains:

- Main query
- SELECT subquery
- WHERE subquery

and all three need to work with the `2013/2014` season.

The filter may need to appear in all three places.

Conceptually:

    Main Query
    WHERE season = '2013/2014'

        ↓

    SELECT Subquery
    WHERE season = '2013/2014'

        ↓

    WHERE Subquery
    WHERE season = '2013/2014'

Each filter controls the data processed by that particular query.

---

# 18. 🧩 Example Structure with Multiple Subqueries

A complex query might look like:

    SELECT
        l.name AS league,

        -- SELECT subquery
        (
            SELECT AVG(home_goal + away_goal)
            FROM match
            WHERE season = '2013/2014'
        ) AS overall_avg

    FROM league AS l

    -- FROM subquery
    LEFT JOIN
        (
            SELECT
                country_id,
                AVG(home_goal + away_goal) AS avg_goals
            FROM match
            WHERE season = '2013/2014'
            GROUP BY country_id
        ) AS sub
        ON l.country_id = sub.country_id

    -- Main query filter
    WHERE l.id IN
        (
            -- WHERE subquery
            SELECT country_id
            FROM match
            WHERE season = '2013/2014'
        );

This is intentionally complex to demonstrate that multiple subqueries can exist in one query.

---

# 19. 🔍 Identify Each Subquery

When reading a complex query, try to identify the different levels.

### SELECT subquery

Look inside:

    SELECT
        (
            SELECT ...
        )

### FROM subquery

Look inside:

    FROM
        (
            SELECT ...
        ) AS subquery

### WHERE subquery

Look inside:

    WHERE column IN
        (
            SELECT ...
        )

---

# 20. 🧠 A Useful Reading Strategy

When a SQL query becomes very long, don't try to understand everything at once.

Read it from the outside inward.

### Step 1 — Find the main query

Identify:

    SELECT
    FROM
    WHERE
    GROUP BY

### Step 2 — Find subqueries

Look for:

    (
        SELECT ...
    )

### Step 3 — Identify what each subquery returns

Ask:

> Does it return one value, a list, or a table?

### Step 4 — Check filters

Look for:

    WHERE ...

inside every subquery.

### Step 5 — Follow the data

Ask:

> What data is being calculated first, and how is that result used by the outer query?

---

# 21. 📊 Subquery Type Quick Reference

| Location | Common Purpose | Typical Result |
|---|---|---|
| `SELECT` | Add summary/calculated value | Single value |
| `FROM` | Prepare or restructure data | Table-like result |
| `WHERE` | Filter based on another query | Single value or list |

### Easy memory trick:

    SELECT → Calculate
    FROM   → Prepare
    WHERE  → Filter

# 22. ⚠️ Common Mistakes

## Mistake 1 — Forgetting a subquery filter

Incorrect when the comparison should only use 2013/2014:

    SELECT AVG(home_goal + away_goal)
    FROM match;

Correct:

    SELECT AVG(home_goal + away_goal)
    FROM match
    WHERE season = '2013/2014';

---

## Mistake 2 — Poor indentation

Avoid putting an entire complex query on one line.

Instead, separate:

    SELECT
    FROM
    JOIN
    WHERE
    GROUP BY

and indent nested queries.

---

## Mistake 3 — Not commenting complex logic

For a complicated calculation, add a comment:

    -- Calculate the difference from the overall season average

---

## Mistake 4 — Using unnecessary subqueries

Before adding another subquery, ask:

    "Can I solve this more simply?"

---

## Mistake 5 — Forgetting that subqueries operate independently

Remember:

> A filter in the main query does not automatically filter a subquery.

---

# 🔑 Key Takeaways

- SQL allows **multiple subqueries** in a single query.
- Subqueries can appear in `SELECT`, `FROM`, and `WHERE`.
- Multiple subqueries can make queries difficult to read.
- Proper formatting makes complex SQL easier to understand.
- Use comments to explain complicated logic.
- Use `/* ... */` for multi-line comments.
- Use `--` for inline comments.
- Properly indent subqueries.
- Properly indent long `CASE` statements and complex calculations.
- Always check whether a subquery is actually necessary.
- Additional subqueries may increase processing requirements.
- Filters in the main query and subqueries are **independent**.
- If every calculation should use the same season or date range, make sure the appropriate filter appears in every relevant query.
