# ⚽ COUNT Using CASE WHEN

## 📝 Overview

We want to find out whether the **number of soccer matches played in each European country differs across seasons**.

Using the European Soccer Database, we will count matches for each country in:

- 📅 `2012/2013`
- 📅 `2013/2014`

The key technique is combining:

    COUNT()

with:

    CASE WHEN

This allows us to count only the matches belonging to a specific season.

---

## 🎯 Instructions

**100 XP**

- Create a `CASE WHEN` statement counting the matches played in the `'2012/2013'` season.
- Create a `CASE WHEN` statement counting the matches played in the `'2013/2014'` season, aliasing it as `matches_2013_2014`.

---

# 💡 Solution

    SELECT 
        c.name AS country,

        -- Count matches in 2012/2013
        COUNT(
            CASE 
                WHEN m.season = '2012/2013' 
                THEN m.id 
            END
        ) AS matches_2012_2013,

        -- Count matches in 2013/2014
        COUNT(
            CASE 
                WHEN m.season = '2013/2014' 
                THEN m.id 
            END
        ) AS matches_2013_2014

    FROM country AS c

    LEFT JOIN match AS m
        ON c.id = m.country_id

    GROUP BY country;

---

# 🔍 Understanding the Query

## 1. Select the Country

    SELECT c.name AS country

The `country` table contains the names of the European countries.

For example:

| country |
|---|
| Belgium |
| England |
| France |
| Germany |
| Italy |
| Spain |

---

## 2. COUNT + CASE for 2012/2013

    COUNT(
        CASE 
            WHEN m.season = '2012/2013' 
            THEN m.id 
        END
    ) AS matches_2012_2013

The `CASE` checks whether a match belongs to the `2012/2013` season.

### If TRUE:

    THEN m.id

The match ID is returned.

### If FALSE:

There is no `ELSE`, so SQL returns:

    NULL

Then `COUNT()` counts the non-NULL match IDs.

### 🧠 In simple terms:

    Is the match from 2012/2013?
            ↓
          Yes
            ↓
       Return m.id
            ↓
        COUNT it

If it is not from that season:

    Return NULL
            ↓
       Do not COUNT it

---

# 📅 3. COUNT Matches in 2013/2014

The same pattern is used for the next season:

    COUNT(
        CASE 
            WHEN m.season = '2013/2014' 
            THEN m.id 
        END
    ) AS matches_2013_2014

The only difference is the season being tested.

---

# 🔗 4. LEFT JOIN

    FROM country AS c

    LEFT JOIN match AS m
        ON c.id = m.country_id

We join the `country` table to the `match` table using:

    c.id = m.country_id

### Why use `LEFT JOIN`?

A `LEFT JOIN` keeps **all countries from the `country` table**, even if there are no matching records in the `match` table.

This is useful when we want a complete list of countries.

Conceptually:

    country
       ↓
    LEFT JOIN
       ↓
    match

Every country remains in the result.

---

# 📊 5. GROUP BY Country

    GROUP BY country

We want one summary row for each country.

Without `GROUP BY`, the `COUNT()` would calculate totals across the entire result.

With:

    GROUP BY country

SQL calculates the counts **separately for each country**.

# 🧠 Why Use `m.id` in the CASE?

You could technically return another non-NULL column, but `m.id` is a natural choice because every match has a unique ID.

For example:

    CASE
        WHEN m.season = '2012/2013'
        THEN m.id
    END

returns the match ID only when the condition is true.

Then:

    COUNT(...)

counts those returned IDs.

---

# 🔄 The General Pattern

This is a very important SQL pattern:

    COUNT(
        CASE
            WHEN condition
            THEN column
        END
    )

Think of it as:

> **Count only the rows where the condition is true.**

For example:

### Count 2012/2013 matches

    COUNT(
        CASE
            WHEN season = '2012/2013'
            THEN id
        END
    )

### Count 2013/2014 matches

    COUNT(
        CASE
            WHEN season = '2013/2014'
            THEN id
        END
    )

---

# 🔑 Why Not Just Use WHERE?

A `WHERE` condition would remove rows from the entire query.

For example:

    WHERE m.season = '2012/2013'

would remove all `2013/2014` matches.

But we want **both seasons in separate columns**.

That's why `CASE WHEN` is useful.

### ❌ Using WHERE

    WHERE m.season = '2012/2013'

Result:

    Country | 2012/2013
    --------|----------
    England | 380
    Spain   | 380

The 2013/2014 data is gone.

### ✅ Using CASE

    COUNT(
        CASE
            WHEN m.season = '2012/2013'
            THEN m.id
        END
    )

    COUNT(
        CASE
            WHEN m.season = '2013/2014'
            THEN m.id
        END
    )

Result:

    Country | 2012/2013 | 2013/2014
    --------|------------|------------
    England | 380        | 380
    Spain   | 380        | 380

Both seasons can be compared side by side.

---

# 📊 CASE + COUNT = Conditional Counting

This technique is called **conditional aggregation**.

The basic structure is:

    COUNT(
        CASE
            WHEN condition THEN value
        END
    )

You can use it to create multiple summary columns.

For example:

    COUNT(CASE WHEN season = '2011/2012' THEN id END)
    COUNT(CASE WHEN season = '2012/2013' THEN id END)
    COUNT(CASE WHEN season = '2013/2014' THEN id END)
    COUNT(CASE WHEN season = '2014/2015' THEN id END)

Each `CASE` creates a separate condition, and each `COUNT()` produces a separate column.

---

# 🎯 Key Takeaways

- `CASE WHEN` can be placed inside `COUNT()`.
- `COUNT(CASE WHEN ... THEN id END)` performs **conditional counting**.
- `COUNT()` ignores `NULL` values.
- If there is no `ELSE`, unmatched `CASE` conditions return `NULL`.
- `LEFT JOIN` keeps all countries from the `country` table.
- `GROUP BY` creates one set of counts for each country.
- Using multiple `CASE` statements lets you compare categories or seasons in **separate columns**.
- `WHERE` filters rows before aggregation, while `CASE` lets you perform **different conditional aggregations within the same result**.
