# 🎯 Filtering with More Complex Subquery Conditions

## 📌 Objective

Generate a list of teams that scored **8 or more goals in a home match**.

This exercise builds on list-based subqueries, but now the **subquery has its own `WHERE` condition**.

---

## 🧠 Key Concept

A subquery can contain its own filtering conditions.

Instead of:

    SELECT hometeam_id
    FROM match

We can filter the subquery itself:

    SELECT hometeam_id
    FROM match
    WHERE home_goal >= 8

The subquery therefore returns only the teams that scored **8 or more home goals**.

---

## 🔍 Step-by-Step

### 1. Find matches with 8 or more home goals

    SELECT hometeam_id
    FROM match
    WHERE home_goal >= 8;

This searches the `match` table and keeps only matches where:

    home_goal >= 8

---

### 2. Return the home team IDs

The subquery returns the `hometeam_id` for those matches.

Conceptually:

    hometeam_id
    -----------
    123
    456
    789
    ...

These IDs represent teams that scored at least 8 goals in a home match.

---

### 3. Use `IN` in the outer query

The outer query checks:

    WHERE team_api_id IN (...)

This means:

> Include teams whose `team_api_id` appears in the list generated by the subquery.

---

## 💻 Complete Query

    SELECT
        team_long_name,
        team_short_name
    FROM team
    WHERE team_api_id IN
        (
            SELECT hometeam_id
            FROM match
            WHERE home_goal >= 8
        );

---

## 🧩 Understanding the Query

### Outer Query

    SELECT
        team_long_name,
        team_short_name
    FROM team

This retrieves the names of the teams.

---

### `IN`

    WHERE team_api_id IN (...)

`IN` keeps teams whose IDs are present in the subquery result.

---

### Inner Query

    SELECT hometeam_id
    FROM match
    WHERE home_goal >= 8

The inner query does two things:

1. Finds matches with at least 8 home goals.
2. Returns the home team ID from those matches.

---

## 🔄 How the Query Works

Think of the process as:

    match table
         ↓
    Filter home_goal >= 8
         ↓
    Get hometeam_id
         ↓
    Create a list of qualifying team IDs
         ↓
    Compare with team_api_id
         ↓
    IN
         ↓
    Return matching team names

## 🆚 Previous Exercise vs. This Exercise

### Previous Exercise

The subquery returned **all unique home teams**:

    SELECT DISTINCT hometeam_id
    FROM match

Then:

    WHERE team_api_id NOT IN (...)

The goal was to **exclude** teams from the list.

### This Exercise

The subquery first filters matches:

    SELECT hometeam_id
    FROM match
    WHERE home_goal >= 8

Then:

    WHERE team_api_id IN (...)

The goal is to **include** teams from the list.

---

## 📊 `IN` vs. `NOT IN`

| Operator | Meaning |
|---|---|
| `IN` | Include values found in the subquery |
| `NOT IN` | Exclude values found in the subquery |

### `IN` example

    WHERE team_api_id IN (
        SELECT hometeam_id
        FROM match
        WHERE home_goal >= 8
    )

➡️ Include teams that scored 8+ goals at home.

### `NOT IN` example

    WHERE team_api_id NOT IN (
        SELECT DISTINCT hometeam_id
        FROM match
    )

➡️ Exclude teams that appeared as home teams.

---

## ⭐ Important Point: The Subquery Has Its Own `WHERE`

This is the main lesson.

The outer query has:

    WHERE team_api_id IN (...)

The subquery also has its own:

    WHERE home_goal >= 8

So you can think of it as:

    Outer query
        ↓
    Find teams
        ↓
    IN
        ↓
    Subquery
        ↓
    Filter matches
        ↓
    home_goal >= 8

A subquery is essentially a **complete query nested inside another query**.

---

## 🔑 General Pattern

You can use this pattern whenever you need to filter a list before using it:

    SELECT columns
    FROM table1
    WHERE column1 IN
        (
            SELECT column2
            FROM table2
            WHERE condition
        );

### Example

    SELECT team_long_name
    FROM team
    WHERE team_api_id IN
        (
            SELECT hometeam_id
            FROM match
            WHERE home_goal >= 8
        );

---

## 🧠 Key Takeaways

- A subquery can have its **own `WHERE` clause**.
- The subquery can filter its source data before returning values.
- `IN` is useful when the subquery returns a **list of values**.
- The outer query uses that list to filter its own table.
- The subquery does not need to return unique values for `IN` to work.
- The columns being compared should contain compatible values.

### Quick Reference

| SQL Concept | Purpose |
|---|---|
| `IN` | Include values found in a list |
| `NOT IN` | Exclude values found in a list |
| `WHERE` inside subquery | Filter the subquery's data |
| `hometeam_id` | Identify the home team |
| `home_goal >= 8` | Find matches with 8+ home goals |
| Nested `SELECT` | Use one query inside another |
