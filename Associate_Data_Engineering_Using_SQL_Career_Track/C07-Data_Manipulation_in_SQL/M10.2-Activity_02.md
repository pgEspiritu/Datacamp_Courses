# 🧩 Organizing with CTEs

## 🎯 Overview

Previously, we modified a query from Chapter 2 by replacing a subquery with a **Common Table Expression (CTE)**.

This time, we will expand the idea by using a CTE to examine the details of **very high-scoring matches**.

Just like a subquery in the `FROM` clause, you can also use **joins inside a CTE**.

The CTE will:

1. 🔗 Join the `match` and `league` tables.
2. 🏷️ Add the league name to each match.
3. 🧮 Calculate the total goals.
4. 📋 Make the prepared data available to the main query.
5. 🔎 Let the main query filter matches with 10 or more total goals.

---

# 📝 Instructions

**100 XP**

- Declare your CTE, where you create a list of all matches with the league `name`.
- Select the `league`, `date`, `home`, and `away` goals **from** the CTE.
- **Filter** the main query for matches with **10 or more** goals.

---

# ✅ Answer

    -- Set up your CTE
    WITH match_list AS (

        -- Select the league name, date, home, and away goals
        SELECT
            l.name AS league,
            m.date,
            m.home_goal,
            m.away_goal,
            (m.home_goal + m.away_goal) AS total_goals
        FROM match AS m
        LEFT JOIN league AS l
            ON m.country_id = l.id
    )

    -- Select the league, date, home, and away goals from the CTE
    SELECT
        league,
        date,
        home_goal,
        away_goal
    FROM match_list

    -- Filter by total goals
    WHERE total_goals >= 10;

---

# 🔍 Step-by-Step Explanation

## 1️⃣ Declare the CTE

The query begins with:

    WITH match_list AS (

        ...
    )

This creates a CTE named:

    match_list

Think of `match_list` as a temporary table containing the data prepared by the CTE.

---

# 2️⃣ Select Match Information

Inside the CTE, we select:

    SELECT
        l.name AS league,
        m.date,
        m.home_goal,
        m.away_goal,
        (m.home_goal + m.away_goal) AS total_goals

The columns have different purposes:

| Column | Purpose |
|:---|:---|
| `l.name AS league` | League name |
| `m.date` | Match date |
| `m.home_goal` | Goals scored by home team |
| `m.away_goal` | Goals scored by away team |
| `total_goals` | Combined home + away goals |

---

# 3️⃣ Calculate Total Goals

The CTE creates a calculated column:

    (m.home_goal + m.away_goal) AS total_goals

For example:

| home_goal | away_goal | total_goals |
|---:|---:|---:|
| 5 | 5 | 10 |
| 6 | 4 | 10 |
| 7 | 5 | 12 |
| 3 | 4 | 7 |

This calculated column will be used by the main query to filter the matches.

💡 Instead of repeating:

    home_goal + away_goal

in the main query, we calculate it once in the CTE and give it a meaningful name:

    total_goals

---

# 4️⃣ Join the `match` and `league` Tables Inside the CTE

The CTE uses:

    FROM match AS m
    LEFT JOIN league AS l
        ON m.country_id = l.id

This is important because the `match` table contains the match information, while the `league` table contains the league name.

The relationship is:

    match.country_id
          ↓
    league.id

The join allows us to retrieve:

    l.name AS league

for each match.

---

# 🧩 CTEs Can Contain JOINs

A common misconception is that a CTE can only contain a simple `SELECT`.

It can contain many normal SQL operations, including:

- `SELECT`
- `FROM`
- `JOIN`
- `WHERE`
- `GROUP BY`
- `HAVING`
- Aggregate functions
- Calculated columns
- Other subqueries

For example:

    WITH match_list AS (
        SELECT
            l.name AS league,
            m.date,
            m.home_goal,
            m.away_goal,
            m.home_goal + m.away_goal AS total_goals
        FROM match AS m
        LEFT JOIN league AS l
            ON m.country_id = l.id
    )

The CTE itself performs a `LEFT JOIN`.

---

# 5️⃣ Query the CTE

After the CTE is declared, the main query uses:

    FROM match_list

This is similar to querying a normal table.

The main query selects:

    SELECT
        league,
        date,
        home_goal,
        away_goal

Notice that we don't need to write:

    m.home_goal

or:

    l.name

because the main query is no longer directly querying those original tables.

It is querying:

    match_list

---

# 6️⃣ Filter for 10 or More Goals

The main query uses:

    WHERE total_goals >= 10;

This keeps only matches where the combined number of goals is at least 10.

For example:

| league | date | home_goal | away_goal | total_goals | Included? |
|:---|:---|---:|---:|---:|:---|
| League A | 2013-01-01 | 5 | 5 | 10 | ✅ |
| League B | 2013-02-01 | 6 | 4 | 10 | ✅ |
| League C | 2013-03-01 | 7 | 5 | 12 | ✅ |
| League D | 2013-04-01 | 3 | 4 | 7 | ❌ |

Only the first three rows would appear in the final result.

---

# 🧠 Why Calculate `total_goals` Inside the CTE?

We could technically write:

    WHERE home_goal + away_goal >= 10

in the main query.

However, creating:

    (m.home_goal + m.away_goal) AS total_goals

inside the CTE makes the logic easier to read.

The CTE prepares the data:

    match
      ↓
    JOIN league
      ↓
    Calculate total_goals
      ↓
    match_list

Then the main query analyzes the prepared data:

    match_list
      ↓
    WHERE total_goals >= 10
      ↓
    Final result

This is one of the main benefits of using CTEs.

---

# 🔄 Query Flow

The complete data flow is:

    ┌───────────────────────┐
    │       match           │
    └───────────┬───────────┘
                │
                │ LEFT JOIN
                ↓
    ┌───────────────────────┐
    │       league          │
    └───────────┬───────────┘
                │
                ↓
       ┌─────────────────┐
       │     CTE         │
       │   match_list    │
       │                 │
       │ league          │
       │ date            │
       │ home_goal       │
       │ away_goal       │
       │ total_goals     │
       └────────┬────────┘
                │
                ↓
       WHERE total_goals >= 10
                │
                ↓
          Final result

# 🆚 Without CTE vs With CTE

## ❌ Without a CTE

You could write the join and filtering directly:

    SELECT
        l.name AS league,
        m.date,
        m.home_goal,
        m.away_goal
    FROM match AS m
    LEFT JOIN league AS l
        ON m.country_id = l.id
    WHERE (m.home_goal + m.away_goal) >= 10;

This works, but all the logic is in one query.

---

## ✅ With a CTE

Using a CTE separates the preparation from the filtering:

    WITH match_list AS (
        SELECT
            l.name AS league,
            m.date,
            m.home_goal,
            m.away_goal,
            (m.home_goal + m.away_goal) AS total_goals
        FROM match AS m
        LEFT JOIN league AS l
            ON m.country_id = l.id
    )

    SELECT
        league,
        date,
        home_goal,
        away_goal
    FROM match_list
    WHERE total_goals >= 10;

### 💡 Advantage

The CTE clearly communicates:

> "First, prepare a match list containing league information and total goals. Then, use that prepared data to find high-scoring matches."

---

# 🔑 Key Takeaways

- 🧩 A CTE is declared using `WITH`.
- 🏷️ `match_list` is the name of the CTE.
- 🔗 A CTE can contain a `JOIN`.
- `match` is joined to `league` using:
  
    m.country_id = l.id

- 🧮 `total_goals` is calculated inside the CTE.
- The main query treats `match_list` like a table.
- The main query can filter using the calculated `total_goals` column.
- `WHERE total_goals >= 10` keeps matches with 10 or more total goals.
- CTEs help separate **data preparation** from **data analysis**.

# ⚡ Quick Reference

## CTE with JOIN

    WITH cte_name AS (
        SELECT
            ...
        FROM table1
        LEFT JOIN table2
            ON table1.key = table2.key
    )

    SELECT
        ...
    FROM cte_name
    WHERE ...;

## CTE with a Calculated Column

    WITH match_list AS (
        SELECT
            home_goal,
            away_goal,
            (home_goal + away_goal) AS total_goals
        FROM match
    )

    SELECT
        home_goal,
        away_goal,
        total_goals
    FROM match_list
    WHERE total_goals >= 10;

# 🎯 Final Mental Model

### CTE = Prepare first, analyze second

    WITH match_list AS (
        -- 🔗 JOIN tables
        -- 🧮 Calculate columns
        -- 🏷️ Give the result a name
    )

    SELECT
        -- 📋 Select what you need
    FROM match_list
    WHERE
        -- 🔎 Filter the prepared data

### Remember:

> **A CTE can contain joins, calculations, filters, and other SQL operations. It creates a named result that the main query can use like a table.**
