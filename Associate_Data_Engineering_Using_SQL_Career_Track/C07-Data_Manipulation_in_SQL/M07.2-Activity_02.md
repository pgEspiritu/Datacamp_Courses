# 🧩 Add a Subquery in FROM

## 🎯 Objective

In the previous exercise, we created a dataset showing the average home and away goals for each match stage in the `2012/2013` season.

In this exercise, we will take that query and turn it into a **subquery in the `FROM` clause**.

The goal is to find:

> **Stages where the average total goals are higher than the overall average total goals for the 2012/2013 season.**

---

# 📝 Original Question

In the previous exercise, you created a data set listing the average home and away goals in each match stage of the `2012/2013` match season.

In this next step, you will turn the main query into a **subquery** to extract a list of stages where the average total goals in a stage is higher than the **overall average** for total goals in a match.

### Instructions

- Calculate the average total goals from the `match` table for each stage in the `FROM` clause subquery.
- Add a subquery to the `WHERE` clause that calculates the overall average total goals.
- **Filter** the main query for stages where the average total goals is **higher than** the overall average.
- Select the `stage` and `avg_goals` columns from the `s` subquery into the main query.

---

# ✅ Answer

    SELECT

        -- Select the stage and average goals from the subquery
        stage,

        ROUND(avg_goals, 2) AS avg_goals

    FROM

        -- Calculate average goals for each stage in 2012/2013
        (
            SELECT
                stage,
                AVG(home_goal + away_goal) AS avg_goals
            FROM match
            WHERE season = '2012/2013'
            GROUP BY stage
        ) AS s

    WHERE

        -- Keep only stages above the overall average
        s.avg_goals >
        (
            SELECT AVG(home_goal + away_goal)
            FROM match
            WHERE season = '2012/2013'
        );

---

# 🔍 How the Query Works

This query contains **two subqueries**:

1. A subquery in the `FROM` clause
2. A subquery in the `WHERE` clause

The main query then compares the results of those two calculations.

---

# 1. 📦 FROM Subquery

The first subquery is:

    (
        SELECT
            stage,
            AVG(home_goal + away_goal) AS avg_goals
        FROM match
        WHERE season = '2012/2013'
        GROUP BY stage
    ) AS s

This creates a temporary table-like result.

It calculates:

    Average total goals
    ↓
    For each stage
    ↓
    During 2012/2013

---

# 2. 🧮 Calculate Total Goals

The expression:

    home_goal + away_goal

calculates the total goals in each match.

Example:

    home_goal = 3
    away_goal = 2

    Total goals = 3 + 2
                = 5

Then:

    AVG(home_goal + away_goal)

calculates the average total goals.

---

# 3. 📊 Group by Stage

The subquery contains:

    GROUP BY stage

This means SQL calculates a separate average for each stage.

Conceptually:

| stage | avg_goals |
|---|---:|
| Stage 1 | 2.40 |
| Stage 2 | 2.75 |
| Stage 3 | 2.90 |
| Stage 4 | 3.10 |

These values become the result of the `FROM` subquery.

---

# 4. 🏷️ Give the Subquery an Alias

The subquery is followed by:

    AS s

This gives the subquery the name:

    s

You can then refer to its columns as:

    s.stage

    s.avg_goals

For example:

    WHERE s.avg_goals > ...

### ⚠️ Important

A subquery in the `FROM` clause needs an alias in many SQL systems.

Here:

    ) AS s

is the alias.

---

# 5. 🎯 The Main Query

The main query is:

    SELECT
        stage,
        ROUND(avg_goals, 2) AS avg_goals

    FROM
        (...) AS s

The main query is now querying the **result of the subquery**.

Think of `s` as a temporary table:

    s
    ┌─────────┬───────────┐
    │ stage   │ avg_goals │
    ├─────────┼───────────┤
    │ Stage 1 │ 2.40      │
    │ Stage 2 │ 2.75      │
    │ Stage 3 │ 2.90      │
    │ Stage 4 │ 3.10      │
    └─────────┴───────────┘

The outer query can now work with this result.

---

# 6. 📊 Calculate the Overall Average

The `WHERE` clause contains another subquery:

    (
        SELECT AVG(home_goal + away_goal)
        FROM match
        WHERE season = '2012/2013'
    )

This calculates the overall average total goals across **all matches in the 2012/2013 season**.

For example:

    Overall average = 2.68

This is a single numeric value.

---

# 7. 🔎 Compare Stage Average with Overall Average

The main filter is:

    WHERE s.avg_goals >
        (
            SELECT AVG(home_goal + away_goal)
            FROM match
            WHERE season = '2012/2013'
        )

In plain English:

> Keep only stages where the stage's average goals are greater than the overall average goals.

---

# 8. 🧮 Example

Suppose the overall average is:

    2.68

And the stage averages are:

| stage | avg_goals |
|---|---:|
| Stage 1 | 2.40 |
| Stage 2 | 2.75 |
| Stage 3 | 2.90 |
| Stage 4 | 2.50 |

The filter:

    avg_goals > 2.68

would keep:

| stage | avg_goals |
|---|---:|
| Stage 2 | 2.75 |
| Stage 3 | 2.90 |

Stage 1 and Stage 4 would be excluded.

---

# 9. 🧠 Why Use a FROM Subquery?

The `FROM` subquery allows us to first create a summarized dataset:

    Stage → Average Goals

Then the outer query can treat that summarized result like a table.

This is useful because we can filter the calculated `avg_goals` in the outer query.

The process is:

    MATCH DATA
        ↓
    GROUP BY STAGE
        ↓
    CALCULATE AVERAGE GOALS
        ↓
    Temporary Result (s)
        ↓
    FILTER avg_goals
        ↓
    FINAL RESULT

---

# 10. 🔄 Query Structure

This exercise has three query levels:

    ┌──────────────────────────────┐
    │ Main Query                   │
    │ SELECT stage, avg_goals      │
    │ FROM ( ... ) AS s            │
    │ WHERE avg_goals > ( ... )    │
    └──────────────┬───────────────┘
                   │
          ┌────────┴─────────┐
          ↓                  ↓
    FROM Subquery       WHERE Subquery
          ↓                  ↓
    Avg goals by        Overall average
    stage               for season
          ↓                  ↓
    2012/2013           2012/2013

---

# 11. 🧩 Identify the Two Subqueries

## FROM Subquery

    (
        SELECT
            stage,
            AVG(home_goal + away_goal) AS avg_goals
        FROM match
        WHERE season = '2012/2013'
        GROUP BY stage
    ) AS s

### Purpose:

Create average goals for each stage.

### Result:

Multiple rows.

---

## WHERE Subquery

    (
        SELECT AVG(home_goal + away_goal)
        FROM match
        WHERE season = '2012/2013'
    )

### Purpose:

Calculate the overall average.

### Result:

One value.

---

# 12. 📌 Difference Between the Two Subqueries

| Subquery | Location | Result | Purpose |
|---|---|---|---|
| Stage average | `FROM` | Multiple rows | Creates stage-level dataset |
| Overall average | `WHERE` | One value | Provides comparison value |

This is a great example of why different subquery locations have different purposes.

---

# 13. ⚠️ Notice the Filters

The `FROM` subquery has:

    WHERE season = '2012/2013'

The `WHERE` subquery also has:

    WHERE season = '2012/2013'

Both are necessary.

### FROM subquery filter

Ensures the stage averages are based only on:

    2012/2013

### WHERE subquery filter

Ensures the comparison value is the overall average for:

    2012/2013

---

# 14. 🧠 Important Concept: Subqueries Are Independent

Do not assume that this:

    WHERE season = '2012/2013'

in one query automatically affects another query.

Each subquery operates independently.

Therefore:

    FROM subquery
        → needs its own filter

    WHERE subquery
        → needs its own filter

---

# 15. 📐 Why `ROUND()` Is in the Main Query

The `FROM` subquery calculates:

    AVG(home_goal + away_goal) AS avg_goals

The outer query then uses:

    ROUND(avg_goals, 2)

This rounds the final displayed average to two decimal places.

You could also round inside the subquery, but keeping the underlying average available and rounding in the outer query is clear and useful.

---

# 16. 🔑 Key Takeaways

- A subquery can be placed inside the `FROM` clause.
- A `FROM` subquery acts like a temporary table.
- A `FROM` subquery can return multiple rows and columns.
- A `FROM` subquery must be given an alias, such as `AS s`.
- The outer query can reference columns created by the subquery.
- A second subquery can be used inside `WHERE`.
- The `WHERE` subquery calculates the overall average.
- The outer query compares stage averages with the overall average.
- Filters inside different queries are independent.
- Both subqueries need the `2012/2013` filter for this exercise.
- `GROUP BY stage` calculates a separate average for each stage.

---

# 🧠 Mental Model

Remember:

> **FROM subquery = Build the summarized dataset.**

> **WHERE subquery = Calculate the comparison value.**

> **Main query = Compare and return the desired rows.**

In this exercise:

    MATCH DATA
        ↓
    Average goals by stage
        ↓
    FROM subquery AS s
        ↓
    Compare s.avg_goals
        ↓
    Against overall season average
        ↓
    Return stages above the average

### ⭐ Easy memory trick

    FROM → PREPARE
    WHERE → COMPARE
    SELECT → DISPLAY

---

# 🎯 Final Takeaway

This exercise demonstrates how a `FROM` subquery and a `WHERE` subquery can work together.

The `FROM` subquery creates:

    stage + average goals

The `WHERE` subquery creates:

    overall average goals

The main query then asks:

    Is stage average > overall average?

Only stages satisfying that condition are returned.
