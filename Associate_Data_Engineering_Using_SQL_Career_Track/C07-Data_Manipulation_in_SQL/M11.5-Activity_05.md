# 🧩 Get Team Names with CTEs

## 📝 Exercise 2/3 — Declare the Home CTE

### 🎯 Original Question

Declare the query from the previous step as a **Common Table Expression (CTE)**.

Then select everything from the CTE into the main query.

> **Note:** The results will not change at this step. We are only changing how the query is organized.

---

# ✅ Answer

    -- Declare the home CTE
    WITH home AS (
        SELECT
            m.id,
            t.team_long_name AS hometeam
        FROM match AS m
        LEFT JOIN team AS t
            ON m.hometeam_id = t.team_api_id
    )

    -- Select everything from home
    SELECT *
    FROM home;

---

# 🔍 Step-by-Step Explanation

## 1. Declare the CTE

Use the `WITH` keyword:

    WITH home AS (

        ...

    )

Here, `home` is the **name of the CTE**.

Think of it as giving a name to the query from Exercise 1.

### Structure

    WITH cte_name AS (
        query
    )
    SELECT *
    FROM cte_name;

---

## 2. Put the Previous Query Inside the CTE

The query from Exercise 1 becomes:

    WITH home AS (
        SELECT
            m.id,
            t.team_long_name AS hometeam
        FROM match AS m
        LEFT JOIN team AS t
            ON m.hometeam_id = t.team_api_id
    )

Nothing about the actual logic has changed.

It still:

1. Reads from `match`
2. Joins `team`
3. Matches `hometeam_id` to `team_api_id`
4. Retrieves the team name
5. Returns the match ID and home team name

---

## 3. Use the CTE in the Main Query

After declaring the CTE, the main query can use it like a table:

    SELECT *
    FROM home;

The CTE `home` now behaves like an intermediate table for the rest of this SQL statement.

---

# 📊 Result

The result is essentially the same as Exercise 1:

| id | hometeam |
|---:|---|
| 1 | Team A |
| 2 | Team B |
| 3 | Team C |
| 4 | Team D |

The actual values depend on the database.

### 💡 Important

The CTE does **not** change the result.

It changes the **organization and readability of the query**.

---

# 🔄 Subquery vs. CTE

The previous subquery approach would look like:

    SELECT *
    FROM (
        SELECT
            m.id,
            t.team_long_name AS hometeam
        FROM match AS m
        LEFT JOIN team AS t
            ON m.hometeam_id = t.team_api_id
    ) AS home;

The CTE approach is:

    WITH home AS (
        SELECT
            m.id,
            t.team_long_name AS hometeam
        FROM match AS m
        LEFT JOIN team AS t
            ON m.hometeam_id = t.team_api_id
    )
    SELECT *
    FROM home;

Both produce the same type of result.

The CTE simply moves the query definition to the beginning.

---

# 🧠 Why Is This Useful?

Imagine the final query needs several preparation steps.

Instead of writing:

    SELECT ...
    FROM (
        SELECT ...
        FROM (
            SELECT ...
        ) AS something
    ) AS something_else;

You can organize the steps more clearly:

    WITH first_step AS (
        SELECT ...
    ),
    second_step AS (
        SELECT ...
        FROM first_step
    )
    SELECT ...
    FROM second_step;

This makes complex queries easier to read and understand.

At this point, we have:

    WITH home AS (

    WITH home AS (

    SELECT ...

    LEFT JOIN home ...
    LEFT JOIN away ...;

---

# 🔑 Key Takeaways

- `WITH` is used to declare a CTE.
- `home` is the name of the CTE.
- The previous query is placed inside `home AS (...)`.
- The main query can reference the CTE as if it were a table.
- `SELECT * FROM home` retrieves everything from the CTE.
- The results are unchanged compared with the previous exercise.
- 🧩 The main benefit at this stage is **organization and readability**.
- Multiple CTEs can be declared by separating them with commas.

## 📌 Quick Reference

    WITH cte_name AS (

        WHERE ...
    )
