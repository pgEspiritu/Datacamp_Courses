# 🔄 Get Team Names with Correlated Subqueries

## 📌 Overview

Let's solve the same problem using **correlated subqueries**:

> **How do you get both the home and away team names into one final query result?**

In the previous exercise, we used subqueries in the `FROM` statement to retrieve both team names.

This time, we'll use correlated subqueries in the `SELECT` statement.

Although correlated subqueries can make the query easier to write, they may affect performance. This exercise will help us understand that trade-off.

<badge color="warning">Performance note</badge> This query may run more slowly than the previous exercise because the correlated subquery depends on each row of the outer query.

---

# 📝 Exercise 1/2 — Get the Home Team Name

## 🎯 Original Question

Using a correlated subquery in the `SELECT` statement, match the `team_api_id` column from `team` to the `hometeam_id` from `match`.

## ✅ Answer

    SELECT
        m.date,
        (
            SELECT team_long_name
            FROM team AS t
            -- Connect the team's team_api_id to the match's hometeam_id
            WHERE t.team_api_id = m.hometeam_id
        ) AS hometeam
    FROM match AS m;

---

# 🔍 Step-by-Step Explanation

## 1. Start with the `match` table

    FROM match AS m

The `match` table contains the match date and the ID of each team's home and away team.

We use `m` as an alias for `match` so we can refer to its columns easily.

## 2. Add a subquery in the `SELECT` statement

    (
        SELECT team_long_name
        FROM team AS t
        WHERE t.team_api_id = m.hometeam_id
    ) AS hometeam

This subquery retrieves the full team name from the `team` table.

The condition:

    WHERE t.team_api_id = m.hometeam_id

matches the team ID in `team` with the home team ID in the current row of `match`.

The result is given the alias `hometeam`.

## 3. Understand the correlation

The key part is:

    t.team_api_id = m.hometeam_id

- `t.team_api_id` comes from the inner query's `team` table.
- `m.hometeam_id` comes from the outer query's `match` table.

Because the inner query references `m.hometeam_id` from the outer query, it is a **correlated subquery**.

The team name returned depends on the current match row.

---

# 📊 Result Structure

The query returns a result similar to this:

| date | hometeam |
|---|---|
| 2015-08-01 | Team A |
| 2015-08-02 | Team C |
| 2015-08-03 | Team E |

The actual team names and dates depend on the database.

---

# 🧠 How the Correlated Subquery Works

Conceptually, the database performs the following logic for each row of the outer query:

    1. Read a match row
           ↓
    2. Get its hometeam_id
           ↓
    3. Find the matching team_api_id
           ↓
    4. Retrieve team_long_name
           ↓
    5. Return the team name as hometeam

For example, if a match has `hometeam_id = 8634`, the subquery searches the `team` table for the row where `team_api_id = 8634` and returns that team's name.

---

# ⚡ Performance Consideration

A correlated subquery references a value from the outer query. Conceptually, it may need to be evaluated for each row returned by the outer query.

For a large `match` table, this can increase the amount of work required compared with a join-based approach.

However, actual performance depends on the database system, indexes, optimizer, and query structure. Some database optimizers can transform correlated subqueries into more efficient execution plans.

### 💡 Key Point

> Correlated subqueries can be convenient and readable, but always consider performance when working with large datasets.

---

# 🔑 Key Takeaways

- A correlated subquery can be placed inside the `SELECT` statement.
- The inner query retrieves the home team name from the `team` table.
- `t.team_api_id` is matched to `m.hometeam_id`.
- The reference to `m.hometeam_id` makes the subquery correlated.
- `AS hometeam` names the resulting column.
- Correlated subqueries may be slower than joins, depending on the query and database optimizer.

## 📌 Quick Reference

    SELECT
        outer_table.column,
        (
            SELECT inner_table.value
            FROM inner_table
            WHERE inner_table.id = outer_table.related_id
        ) AS result
    FROM outer_table;

**Mental model:**

`Outer row → Related ID → Inner query → Matching value → Result`
