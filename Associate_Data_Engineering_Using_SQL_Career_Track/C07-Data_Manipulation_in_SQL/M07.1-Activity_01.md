# ⚽ ALL the Subqueries EVERYWHERE

## 🎯 Objective

Build a query that examines the **average number of goals scored at each stage of a match**.

This exercise focuses on using a subquery in the `SELECT` clause while also reinforcing the idea that subqueries can appear in different parts of a SQL query.

The goal is to compare:

- The **average total goals for each stage**
- The **overall average total goals for the entire 2012/2013 season**

---

# 📝 Original Question

In soccer leagues, games are played at different *stages*. Winning teams progress from one stage to the next, until they reach the final stage.

The `match` table includes data about the different stages that each match took place in.

In this lesson, you will build a final query across 3 exercises that will contain three subqueries:

- One in the `SELECT` clause
- One in the `FROM` clause
- One in the `WHERE` clause

The final query examines the average goals scored in each stage of a match.

### Question

> Does the average number of goals scored change as the stakes get higher from one stage to the next?

---

# 📋 Instructions

- Extract the average number of total goals in a `SELECT` subquery.
- Calculate the **average** total goals for the specific `stage` in the main query.
- **Filter** both subqueries and the main query so that only data from the **2012/2013** season is included.
- `GROUP` the query by the `m.stage` column.

---

# ✅ Answer

    SELECT

        -- Select the stage and average goals for each stage
        m.stage,

        ROUND(
            AVG(home_goal + m.away_goal),
            2
        ) AS avg_goals,

        -- Select the average overall goals for the 2012/2013 season
        ROUND(
            (
                SELECT AVG(home_goal + away_goal)
                FROM match
                WHERE season = '2012/2013'
            ),
            2
        ) AS overall

    FROM match AS m

    -- Filter for the 2012/2013 season
    WHERE season = '2012/2013'

    -- Group by stage
    GROUP BY m.stage;

---

# 🔍 How the Query Works

## 1. Select the Stage

The first column is:

    m.stage

This identifies the stage in which each match was played.

Because we later use:

    GROUP BY m.stage

SQL will produce one result row for each stage.

---

# 2. Calculate Average Goals per Stage

The main query uses:

    AVG(home_goal + m.away_goal)

This first calculates total goals for each match:

    home_goal + away_goal

Then `AVG()` calculates the average total goals.

Because the query groups by:

    m.stage

the calculation becomes:

    Average total goals for Stage 1
    Average total goals for Stage 2
    Average total goals for Stage 3
    ...

---

# 3. Round the Average

The query uses:

    ROUND(
        AVG(home_goal + m.away_goal),
        2
    )

The `2` means that the result is rounded to **two decimal places**.

For example:

    2.7354 → 2.74

---

# 4. Calculate the Overall Average

The SELECT subquery is:

    (
        SELECT AVG(home_goal + away_goal)
        FROM match
        WHERE season = '2012/2013'
    )

This calculates the average total goals across **all matches in the 2012/2013 season**.

The subquery returns a single value.

That value is displayed as:

    overall

---

# 5. Why Is `overall` the Same for Every Stage?

The subquery does not use:

    GROUP BY stage

It calculates one average for the entire season.

For example:

    overall = 2.68

That value can then appear beside every stage:

| stage | avg_goals | overall |
|---|---:|---:|
| Stage 1 | 2.51 | 2.68 |
| Stage 2 | 2.72 | 2.68 |
| Stage 3 | 2.91 | 2.68 |

The exact values depend on the database.

The important point is:

> `avg_goals` is calculated separately for each stage, while `overall` is calculated once for the entire season.

---

# 6. 📅 Filter the Main Query

The main query contains:

    WHERE season = '2012/2013'

This means that only matches from the `2012/2013` season are included in the stage-level calculation.

Without this filter, the main query would calculate stage averages using matches from all seasons.

---

# 7. 📅 Filter the SELECT Subquery

The subquery also contains:

    WHERE season = '2012/2013'

This is necessary because the subquery operates independently.

It ensures that:

    overall

represents the overall average for **2012/2013 only**.

---

# ⚠️ Important: Filters Are Independent

Remember the previous lesson:

> A filter in the main query does not automatically filter a subquery.

Therefore, these are two separate filters:

### Main query

    WHERE season = '2012/2013'

### SELECT subquery

    WHERE season = '2012/2013'

Both are needed for the intended calculation.

---

# 8. 🧮 Understand the Two Averages

The query calculates two different averages.

### `avg_goals`

    AVG(home_goal + away_goal)

Calculated separately for each:

    stage

### `overall`

    SELECT AVG(home_goal + away_goal)
    FROM match
    WHERE season = '2012/2013'

Calculated across:

    ALL 2012/2013 matches

---

# 9. 📊 Conceptual Result

The result might look like:

| stage | avg_goals | overall |
|---|---:|---:|
| Stage 1 | 2.40 | 2.68 |
| Stage 2 | 2.75 | 2.68 |
| Stage 3 | 2.90 | 2.68 |
| Stage 4 | 3.10 | 2.68 |

Again, these numbers are illustrative.

The structure is what matters.

You can compare each stage's average with the overall average.

---

# 10. 🧠 Reading the Result

The `overall` column acts as a reference point.

For example:

    Stage average = 3.10
    Overall average = 2.68

Difference:

    3.10 - 2.68 = 0.42

So that stage has an average that is 0.42 goals above the overall season average.

Likewise:

    Stage average = 2.40
    Overall average = 2.68

Difference:

    2.40 - 2.68 = -0.28

That stage has an average that is 0.28 goals below the overall season average.

---

# 11. 🔄 Query Processing Mental Model

Think about the query this way:

    Main query
        ↓
    Filter to 2012/2013
        ↓
    Group matches by stage
        ↓
    Calculate average goals per stage

Meanwhile:

    SELECT subquery
        ↓
    Filter to 2012/2013
        ↓
    Calculate overall average goals
        ↓
    Return one value

Then SQL combines the results:

    Stage average + Overall average

---

# 12. 🧩 Breaking Down the SELECT Clause

The SELECT clause contains three pieces:

    SELECT
        m.stage,

        ROUND(
            AVG(home_goal + m.away_goal),
            2
        ) AS avg_goals,

        ROUND(
            (
                SELECT AVG(home_goal + away_goal)
                FROM match
                WHERE season = '2012/2013'
            ),
            2
        ) AS overall

### Column 1

    m.stage

Identifies the stage.

### Column 2

    avg_goals

Average total goals for that stage.

### Column 3

    overall

Overall average total goals for the season.

---

# 13. 📦 Why This Is a SELECT Subquery

The subquery appears inside:

    SELECT

Specifically:

    (
        SELECT AVG(home_goal + away_goal)
        FROM match
        WHERE season = '2012/2013'
    )

It returns **one numeric value**, making it suitable for use as a SELECT column.

---

# 14. ⚠️ SELECT Subquery Rule

A subquery inside `SELECT` should return a **single value**.

### ✅ Good

    (
        SELECT AVG(home_goal + away_goal)
        FROM match
        WHERE season = '2012/2013'
    )

`AVG()` returns one value.

### ❌ Problematic

    (
        SELECT stage
        FROM match
        WHERE season = '2012/2013'
    )

This could return many rows.

A SELECT subquery cannot normally insert multiple rows into a single result column.

---

# 15. 🧠 Subquery Locations

This exercise connects the three subquery locations covered in the lesson.

| Location | Purpose | Typical Result |
|---|---|---|
| `SELECT` | Add a calculated/summary value | Single value |
| `FROM` | Prepare or restructure data | Table-like result |
| `WHERE` | Filter based on another query | Value or list |

### Easy memory trick:

    SELECT → Calculate
    FROM   → Prepare
    WHERE  → Filter

---

# 16. 🧩 Multiple Subqueries in One Query

The overall lesson demonstrates that SQL can contain multiple subqueries.

A complex query could conceptually contain:

    SELECT
        (
            SELECT ...
        )

    FROM
        (
            SELECT ...
        ) AS subquery

    WHERE column IN
        (
            SELECT ...
        );

Each subquery has its own purpose.

---

# 17. ⚠️ Check Every Filter

When working with multiple subqueries, ask:

> "Which data should this particular query process?"

For this exercise:

### Main query

    2012/2013

### SELECT subquery

    2012/2013

If another subquery were added, check whether it also needs:

    WHERE season = '2012/2013'

Do not assume that the main query's filter automatically applies everywhere.

---

# 18. 🔑 Key Takeaways

- A subquery can be placed inside `SELECT`.
- A SELECT subquery should return one value.
- Aggregate functions such as `AVG()` are commonly used in SELECT subqueries.
- `home_goal + away_goal` calculates total goals for each match.
- `AVG()` calculates the average total goals.
- `GROUP BY m.stage` produces a separate average for each stage.
- The SELECT subquery calculates the overall season average.
- The overall average is repeated for every stage because it is one scalar value.
- The main query and subquery need their own filters.
- `ROUND(..., 2)` rounds the result to two decimal places.
- Multiple subqueries can exist in the same SQL query.
- Complex queries should be properly formatted and commented.

              +

    SELECT SUBQUERY
          ↓

              ↓

    Stage Average + Overall Average
