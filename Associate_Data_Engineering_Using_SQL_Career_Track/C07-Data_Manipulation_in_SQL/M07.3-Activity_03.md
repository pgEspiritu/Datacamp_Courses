# 🧩 Add a Subquery in SELECT

## 🎯 Objective

This is the **final step** in the series of exercises on using subqueries everywhere.

In the previous exercise, we used:

- A subquery in `FROM`
- A subquery in `WHERE`

This exercise adds another subquery in `SELECT`.

The final query will therefore contain:

- ✅ `SELECT` subquery
- ✅ `FROM` subquery
- ✅ `WHERE` subquery

The goal is to compare the **average goals for each stage** against the **overall average goals for the 2012/2013 season**.

---

# 📝 Original Question

In the previous exercise, you added a subquery to the `FROM` statement and selected the stages where the number of average goals in a stage exceeded the overall average number of goals in the `2012/2013` match season.

In this final step, you will add a subquery in `SELECT` to compare the average number of goals scored in each stage to the total.

### Instructions

- Create a subquery in `SELECT` that yields the average total goals scored in the `2012/2013` season and stores it in a column named `overall_avg`.
- Create a subquery in `FROM` that calculates the average total goals scored in each stage during the `2012/2013` season.
- Filter the main query for stages where the average total goals exceeds the overall average in `2012/2013`.

---

# ✅ Answer

    SELECT

        -- Select the stage and average goals from s
        stage,

        ROUND(s.avg_goals, 2) AS avg_goal,

        -- Select the overall average for 2012/2013
        (
            SELECT AVG(home_goal + away_goal)
            FROM match
            WHERE season = '2012/2013'
        ) AS overall_avg

    FROM

        -- Calculate the average goals for each stage in 2012/2013
        (
            SELECT
                stage,
                AVG(home_goal + away_goal) AS avg_goals
            FROM match
            WHERE season = '2012/2013'
            GROUP BY stage
        ) AS s

    WHERE

        -- Keep only stages above the overall average
        s.avg_goals >
        (
            SELECT AVG(home_goal + away_goal)
            FROM match
            WHERE season = '2012/2013'
        );

---

# 🔍 How the Query Works

This query contains **three important query levels/components**:

    SELECT subquery
        ↓
    FROM subquery
        ↓
    WHERE subquery

Each one has a different purpose.

---

# 1. 📦 FROM Subquery — Build the Stage Dataset

The `FROM` subquery is:

    (
        SELECT
            stage,
            AVG(home_goal + away_goal) AS avg_goals
        FROM match
        WHERE season = '2012/2013'
        GROUP BY stage
    ) AS s

This creates a temporary table-like result called:

    s

It contains:

    stage
    avg_goals

For example:

| stage | avg_goals |
|---|---:|
| Stage 1 | 2.40 |
| Stage 2 | 2.75 |
| Stage 3 | 2.90 |
| Stage 4 | 2.50 |

The exact values depend on the database.

---

# 2. 🧮 Calculate Average Goals per Stage

Inside the `FROM` subquery:

    AVG(home_goal + away_goal)

first calculates the total goals for each match:

    home_goal + away_goal

Then `AVG()` calculates the average.

Because we use:

    GROUP BY stage

the average is calculated separately for each stage.

---

# 3. 🏷️ Alias the FROM Subquery

At the end of the subquery:

    ) AS s

The alias is:

    s

This allows the main query to refer to the subquery's columns:

    s.stage

    s.avg_goals

For example:

    SELECT
        s.stage,
        s.avg_goals
    FROM (...) AS s;

---

# 4. 📊 SELECT Subquery — Calculate the Overall Average

The new part added in this exercise is:

    (
        SELECT AVG(home_goal + away_goal)
        FROM match
        WHERE season = '2012/2013'
    ) AS overall_avg

This calculates the average total goals across **all matches in the 2012/2013 season**.

It returns one single value.

That value is stored/displayed as:

    overall_avg

---

# 5. 🧠 Why Is the SELECT Subquery Valid?

A subquery inside `SELECT` should return a **single value**.

Here:

    SELECT AVG(home_goal + away_goal)
    FROM match
    WHERE season = '2012/2013'

`AVG()` produces one value.

Therefore, SQL can place that value alongside every row in the result.

Conceptually:

| stage | avg_goal | overall_avg |
|---|---:|---:|
| Stage 1 | 2.40 | 2.68 |
| Stage 2 | 2.75 | 2.68 |
| Stage 3 | 2.90 | 2.68 |
| Stage 4 | 2.50 | 2.68 |

The `overall_avg` value is repeated because it represents the overall season average.

---

# 6. 🔎 WHERE Subquery — Compare Against the Overall Average

The `WHERE` clause contains another subquery:

    WHERE s.avg_goals >
        (
            SELECT AVG(home_goal + away_goal)
            FROM match
            WHERE season = '2012/2013'
        )

This asks:

> Is the stage's average total goals greater than the overall average total goals?

Only stages that satisfy this condition are returned.

---

# 7. 🧮 Example

Suppose the overall average is:

    2.68

And the stage averages are:

| stage | avg_goals |
|---|---:|
| Stage 1 | 2.40 |
| Stage 2 | 2.75 |
| Stage 3 | 2.90 |
| Stage 4 | 2.50 |

The `WHERE` condition is:

    avg_goals > 2.68

Therefore:

    Stage 1 → 2.40 > 2.68 → FALSE
    Stage 2 → 2.75 > 2.68 → TRUE
    Stage 3 → 2.90 > 2.68 → TRUE
    Stage 4 → 2.50 > 2.68 → FALSE

The result would contain:

| stage | avg_goal | overall_avg |
|---|---:|---:|
| Stage 2 | 2.75 | 2.68 |
| Stage 3 | 2.90 | 2.68 |

The numbers above are illustrative.

---

# 8. 📅 Why `2012/2013` Appears Multiple Times

Notice that the season filter appears in multiple places.

### SELECT subquery

    WHERE season = '2012/2013'

### FROM subquery

    WHERE season = '2012/2013'

### WHERE subquery

    WHERE season = '2012/2013'

This is intentional.

Each query operates independently.

---

# 9. ⚠️ Filters Are Independent

A filter in one query does **not automatically filter another query**.

For example:

    FROM subquery
    WHERE season = '2012/2013'

does not automatically mean that the SELECT subquery is also filtered.

Therefore, if the SELECT subquery needs the same season restriction, it must contain:

    WHERE season = '2012/2013'

Likewise, the WHERE subquery needs its own filter.

---

# 10. 🧩 Three Subqueries / Query Components

This final exercise demonstrates the different roles of subqueries.

| Location | Purpose | Result |
|---|---|---|
| `SELECT` | Calculate overall average | One value |
| `FROM` | Calculate average by stage | Multiple rows |
| `WHERE` | Calculate comparison value | One value |

### Easy memory trick:

    SELECT → DISPLAY/CALCULATE
    FROM   → PREPARE
    WHERE  → FILTER/COMPARE

# 11. 🔄 Complete Query Flow

The query can be understood as:

    STEP 1
    Read match data
        ↓
    STEP 2
    Filter to 2012/2013
        ↓
    STEP 3
    Group by stage
        ↓
    STEP 4
    Calculate average goals per stage
        ↓
    STEP 5
    Create temporary dataset "s"
        ↓
    STEP 6
    Calculate overall 2012/2013 average
        ↓
    STEP 7
    Compare stage average > overall average

# 12. 🧠 Think of the FROM Subquery as a Temporary Table

The subquery:

    (
        SELECT
            stage,
            AVG(home_goal + away_goal) AS avg_goals
        FROM match
        WHERE season = '2012/2013'
        GROUP BY stage
    ) AS s

can be thought of as:

    s
    ┌─────────┬───────────┐
    │ stage   │ avg_goals │
    ├─────────┼───────────┤
    │ Stage 1 │ 2.40      │
    │ Stage 2 │ 2.75      │
    │ Stage 3 │ 2.90      │
    │ Stage 4 │ 2.50      │
    └─────────┴───────────┘

The main query then works with `s`.

---

# 13. 🎯 What Does `overall_avg` Mean?

`overall_avg` represents:

> The average total number of goals per match across all matches in the 2012/2013 season.

It is **not** the average for each stage.

That is what `avg_goal` represents.

### Difference:

    avg_goal
    → Average goals for a specific stage

    overall_avg
    → Average goals for the entire season

---

# 14. 📊 Why Include `overall_avg` in the SELECT?

The `WHERE` subquery already calculates the overall average for filtering.

Adding the SELECT subquery lets us **display that comparison value** in the final result.

Without the SELECT subquery, we might only see:

| stage | avg_goal |
|---|---:|
| Stage 2 | 2.75 |
| Stage 3 | 2.90 |

With the SELECT subquery:

| stage | avg_goal | overall_avg |
|---|---:|---:|
| Stage 2 | 2.75 | 2.68 |
| Stage 3 | 2.90 | 2.68 |

Now the comparison value is visible in the output.

---

# 15. ⚠️ `avg_goal` vs. `avg_goals`

The subquery creates:

    AVG(home_goal + away_goal) AS avg_goals

The outer query displays:

    ROUND(s.avg_goals, 2) AS avg_goal

So:

    avg_goals
    → column name inside subquery

    avg_goal
    → column name displayed in final result

This is valid SQL.

---

# 16. 🧮 Why Round Only the Displayed Stage Average?

The outer query uses:

    ROUND(s.avg_goals, 2) AS avg_goal

This rounds the stage average to two decimal places for display.

The comparison itself uses:

    s.avg_goals >
        (
            SELECT AVG(home_goal + away_goal)
            ...
        )

This means the comparison uses the underlying averages rather than their rounded display values.

This avoids unnecessarily changing the comparison because of rounding.

---

# 17. 🔑 Key Takeaways

- A query can contain multiple subqueries.
- Subqueries can appear in `SELECT`, `FROM`, and `WHERE`.
- The `FROM` subquery creates a summarized, table-like dataset.
- The `SELECT` subquery returns one overall numeric value.
- The `WHERE` subquery provides a comparison value.
- `GROUP BY stage` calculates a separate average for each stage.
- The `SELECT` subquery allows the overall average to appear in the final output.
- The `WHERE` subquery filters stages based on the overall average.
- Filters in different queries are independent.
- If each calculation must use `2012/2013`, each relevant subquery needs its own season filter.
- A SELECT subquery must return a single value.
- A FROM subquery can return multiple rows and columns.
- Proper indentation is especially important when multiple subqueries are nested.

            ↓

            ↓
    WHERE SUBQUERY

            ↓

> **FROM prepares the data.**  
> **WHERE filters the data.**  
> **SELECT adds the comparison value.**

This is the key pattern for working with **multiple subqueries in one SQL query**.
