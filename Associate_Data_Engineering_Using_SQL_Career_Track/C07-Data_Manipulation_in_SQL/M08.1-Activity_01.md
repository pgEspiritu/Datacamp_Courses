# 🔗 Getting Started with Correlated Subqueries

## 🎯 Objective

A **correlated subquery** is a subquery that references one or more columns from the **main query**.

Unlike a simple subquery, a correlated subquery **depends on the current row of the main query** and therefore cannot be executed independently.

In this exercise, we use a correlated subquery to find matches where the total goals are more than **3 times the average total goals for that match's country**.

---

# 📝 Original Question

Correlated subqueries are subqueries that reference one or more columns in the main query. Correlated subqueries depend on information in the main query to run, and thus, cannot be executed on their own.

Correlated subqueries are evaluated in SQL once per row of data retrieved—a process that takes a lot more computing power and time than a simple subquery.

In this exercise, you will practice using correlated subqueries to examine matches with scores that are extreme outliers for each country—above 3 times the average score!

### Instructions

- Start the subquery in `WHERE` by taking the **average**/mean of the home and away goals.
- Complete the subquery column references, so that `country_id` is matched in the `main` and `sub` tables.

---

# ✅ Answer

    SELECT
        main.country_id,
        main.date,
        main.home_goal,
        main.away_goal

    FROM match AS main

    WHERE

        -- Filter the main query by the correlated subquery
        (main.home_goal + main.away_goal) >

        (
            -- Calculate 3 times the average total goals
            SELECT AVG((sub.home_goal + sub.away_goal) * 3)

            FROM match AS sub

            -- Match the country of the main row
            -- with the country of the subquery rows
            WHERE main.country_id = sub.country_id
        );

---

# 🔍 What Is a Correlated Subquery?

A correlated subquery is a subquery that **refers to a column from the outer/main query**.

In this example:

    main.country_id = sub.country_id

The subquery uses:

    main.country_id

`main` belongs to the outer query.

Therefore, the subquery depends on the current row being examined by the main query.

---

# 🆚 Simple vs. Correlated Subquery

## Simple Subquery

A simple subquery can run independently.

Example:

    SELECT AVG(home_goal + away_goal)
    FROM match;

It does not depend on the outer query.

The database can calculate the average once and use the result.

---

## Correlated Subquery

The correlated subquery contains:

    WHERE main.country_id = sub.country_id

Because it references `main.country_id`, the result depends on which country the main query is currently processing.

Conceptually:

    Main row
        ↓
    Get its country_id
        ↓
    Find matches from that country
        ↓
    Calculate that country's average
        ↓
    Compare the main match against that average
        ↓
    Move to the next main row

---

# 🧠 The Most Important Part

Look carefully at:

    WHERE main.country_id = sub.country_id

This is what makes the subquery **correlated**.

### `main.country_id`

Comes from the **main query**.

### `sub.country_id`

Comes from the **subquery**.

They are being compared:

    main.country_id = sub.country_id

This means:

> Only calculate the average using matches from the same country as the current main match.

---

# 📊 Understanding the Two Table Aliases

The same table is being used twice:

    FROM match AS main

and:

    FROM match AS sub

They represent two different roles.

| Alias | Role |
|---|---|
| `main` | Match currently being evaluated |
| `sub` | Matches used to calculate the country's average |

This is why aliases are essential here.

---

# 1. 📋 Main Query

The main query starts with:

    SELECT
        main.country_id,
        main.date,
        main.home_goal,
        main.away_goal
    FROM match AS main

This retrieves information about individual matches.

For example, conceptually:

| country_id | date | home_goal | away_goal |
|---:|---|---:|---:|
| 1 | 2013-01-01 | 5 | 1 |
| 1 | 2013-01-05 | 2 | 1 |
| 2 | 2013-01-08 | 4 | 0 |

The main query examines these matches one at a time.

---

# 2. ⚽ Calculate Total Goals

The main query calculates total goals using:

    main.home_goal + main.away_goal

For example:

    home_goal = 5
    away_goal = 1

Therefore:

    5 + 1 = 6

The condition asks whether this total is greater than the country's threshold.

---

# 3. 🧮 The Correlated Subquery

The subquery is:

    (
        SELECT AVG((sub.home_goal + sub.away_goal) * 3)
        FROM match AS sub
        WHERE main.country_id = sub.country_id
    )

It calculates the average of:

    (home_goal + away_goal) * 3

for matches belonging to the same country as the current main row.

---

# 4. 🌍 Match the Country

This line is the key:

    WHERE main.country_id = sub.country_id

Suppose the current main row has:

    main.country_id = 10

The subquery effectively looks at:

    sub.country_id = 10

It ignores matches from other countries.

Then it calculates the average for that country.

---

# 5. 📈 Why Multiply by 3?

The exercise asks for matches with scores above **3 times the average score**.

The query uses:

    AVG((sub.home_goal + sub.away_goal) * 3)

This produces a threshold equivalent to:

    3 × average total goals

For example, suppose a country's average total goals is:

    2.5

Then the threshold is:

    2.5 × 3 = 7.5

A match with:

    8 total goals

would satisfy:

    8 > 7.5

and therefore be returned.

---

# ⚠️ Important SQL Detail

The exercise's expression is:

    AVG((sub.home_goal + sub.away_goal) * 3)

Mathematically, this is equivalent to:

    AVG(sub.home_goal + sub.away_goal) * 3

because multiplying every value by 3 before taking the average produces the same result as multiplying the average by 3.

So you may also see the logic written as:

    (
        SELECT AVG(sub.home_goal + sub.away_goal) * 3
        FROM match AS sub
        WHERE main.country_id = sub.country_id
    )

Both represent the same threshold.

---

# 🔄 How the Correlation Works

Imagine the main query is examining a match from Country A.

### Step 1 — Main row

    main.country_id = A

### Step 2 — Correlated subquery

    WHERE main.country_id = sub.country_id

The subquery selects only matches from Country A.

### Step 3 — Calculate average

    AVG(sub.home_goal + sub.away_goal)

### Step 4 — Multiply by 3

    average × 3

### Step 5 — Compare

    main.home_goal + main.away_goal > country_average × 3

### Step 6 — Move to the next match

The process repeats using the next main row.

---

# 🧠 Simple Mental Model

Think:

    MAIN MATCH
        ↓
    What country is this match from?
        ↓
    Find all matches from that country
        ↓
    Calculate that country's average goals
        ↓
    Multiply by 3
        ↓
    Compare with current match
        ↓
    Is current match > 3× country average?
        ↓
    YES → return match
    NO  → exclude match

---

# 🆚 Simple Subquery vs. Correlated Subquery

| Feature | Simple Subquery | Correlated Subquery |
|---|---|---|
| Depends on main query? | ❌ No | ✅ Yes |
| Can run independently? | ✅ Yes | ❌ No |
| References outer query? | ❌ No | ✅ Yes |
| Usually evaluated | Once | Per relevant outer row |
| Example | `SELECT AVG(...)` | `WHERE main.country_id = sub.country_id` |

---

# ⚡ Why Correlated Subqueries Can Be Expensive

A correlated subquery depends on the current row of the main query.

Conceptually:

    Main row 1 → run subquery
    Main row 2 → run subquery
    Main row 3 → run subquery
    Main row 4 → run subquery
    ...

With a large table, this can require substantially more work than a simple subquery.

This is why correlated subqueries should be used carefully with large datasets.

---

# 🏷️ Why Aliases Matter

Without aliases, it would be difficult to distinguish the two references to `match`.

The query uses:

    match AS main

and:

    match AS sub

Therefore:

    main.home_goal

means the home goals of the current main-query match.

While:

    sub.home_goal

means the home goals of matches being examined inside the subquery.

---

# 🎯 Key Takeaways

- A **correlated subquery** references a column from the main query.
- `main.country_id = sub.country_id` creates the correlation.
- The subquery calculates the average for the **same country** as the current main match.
- `AVG()` calculates the mean total goals.
- Multiplying by `3` creates the extreme-outlier threshold.
- The main query compares the current match's total goals against that threshold.
- A correlated subquery cannot be executed independently because it needs a value from the main query.
- Correlated subqueries can require more processing than simple subqueries.
- Table aliases such as `main` and `sub` make the two query levels easier to distinguish.

---

# 🔑 Quick Reference

## Simple Subquery

    SELECT AVG(home_goal + away_goal)
    FROM match;

➡️ Does not depend on the main query.

## Correlated Subquery

    SELECT AVG(sub.home_goal + sub.away_goal)
    FROM match AS sub
    WHERE main.country_id = sub.country_id;

➡️ Depends on `main.country_id`.

## Correlated Filtering Pattern

    SELECT ...
    FROM table AS main
    WHERE main.value >
        (
            SELECT AVG(sub.value)
            FROM table AS sub
            WHERE main.group_id = sub.group_id
        );

### Meaning:

> Compare each row against the average of its own group.

---

# 🧩 Final Pattern to Remember

    SELECT
        columns
    FROM table AS main
    WHERE main.value >
        (
            SELECT AVG(sub.value)
            FROM table AS sub
            WHERE main.group_id = sub.group_id
        );

### 🧠 Memory Trick

**Correlated = the subquery "looks back" at the current row of the main query.**

    main row
       ↓
    main.group_id
       ↓
    subquery uses that group_id
       ↓
    calculate group-specific value
       ↓
    compare with main row
