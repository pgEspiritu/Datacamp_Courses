# Slide to the Right

Now let's see how *FC Utrecht* performs when they're the away team. You'll notice that the total for the season is at the bottom of the data set you queried. Depending on your results, this could be pretty long, and scrolling down is not very helpful.

In this exercise, you will slightly modify the query from the previous exercise by sorting the data set in reverse order and calculating a backward running total **from the `CURRENT ROW` to the end of the data set** (earliest record).

## Instructions

**100 XP**

- Complete the window function by:
  - Assessing the running **total** of away goals scored by **FC Utrecht**.
  - Assessing the running **average** of away goals scored.
  - Ordering both the running average and running total by `date`, **descending**.

## SQL Code

```sql
SELECT
    -- Select the date and away goals
    date,
    away_goal,

    -- Create a running total sum and running average of away goals
    SUM(away_goal) OVER (
        ORDER BY date DESC
        ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING
    ) AS running_total,

    AVG(away_goal) OVER (
        ORDER BY date DESC
        ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING
    ) AS running_avg

FROM match
WHERE
    awayteam_id = 9908
    AND season = '2011/2012';
```

## Code Explanation

### 1. `SELECT`

```sql
SELECT
    date,
    away_goal,
```

- `SELECT` specifies the columns to display in the result.
- `date` displays the date of each match.
- `away_goal` displays the number of goals FC Utrecht scored as the away team in each match.

### 2. `SUM(away_goal) OVER (...) AS running_total`

```sql
SUM(away_goal) OVER (
    ORDER BY date DESC
    ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING
) AS running_total,
```

- `SUM(away_goal)` calculates the sum of away goals.
- `OVER (...)` defines the window of rows used for the calculation.
- `ORDER BY date DESC` sorts the matches from the most recent to the earliest date.
- `ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING` includes the current match and every subsequent row in the sorted result, continuing to the end of the data set.
- `AS running_total` gives the calculated column the name `running_total`.

**Result:** For each match, the running total represents the goals scored in that match plus the goals scored in all earlier matches in the season.

### 3. `AVG(away_goal) OVER (...) AS running_avg`

```sql
AVG(away_goal) OVER (
    ORDER BY date DESC
    ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING
) AS running_avg
```

- `AVG(away_goal)` calculates the average number of away goals.
- The window definition uses the same date order and range as the running total.
- `AS running_avg` names the resulting column `running_avg`.

**Result:** For each match, the running average represents the average number of away goals per match from the current match through the earliest match of the season.

### 4. `FROM match`

```sql
FROM match
```

Specifies the `match` table as the source of the data.

### 5. `WHERE`

```sql
WHERE
    awayteam_id = 9908
    AND season = '2011/2012';
```

- `awayteam_id = 9908` filters the data to matches where FC Utrecht was the away team.
- `season = '2011/2012'` restricts the results to the 2011/2012 season.
- `AND` requires both conditions to be satisfied.

## Understanding the Window Frame

The key part of this exercise is:

```sql
ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING
```

| Keyword | Meaning |
|---|---|
| `ROWS` | Defines the window frame using individual rows. |
| `CURRENT ROW` | Starts the calculation at the current match. |
| `UNBOUNDED FOLLOWING` | Extends the calculation to the final row of the ordered result. |

Because the dates are sorted in descending order, the first row is the most recent match, and the final row is the earliest match.

### Example

Suppose FC Utrecht scored the following away goals in three matches:

| Match date | Away goals |
|---|---:|
| March 10 | 2 |
| March 3 | 1 |
| February 24 | 3 |

The query calculates the following:

| Match date | Away goals | Running total | Running average |
|---|---:|---:|---:|
| March 10 | 2 | 6 | 2.00 |
| March 3 | 1 | 4 | 2.00 |
| February 24 | 3 | 3 | 3.00 |

- **March 10:** Includes all three matches, so the total is \(2+1+3=6\), and the average is \(6/3=2\).
- **March 3:** Includes March 3 and February 24, so the total is \(1+3=4\), and the average is \(4/2=2\).
- **February 24:** Includes only the current match, so the total and average are both 3.

## Important Takeaway

A backward running total or average calculates values from the current row toward the end of the ordered data set.

- `ORDER BY date DESC` places the newest match first.
- `CURRENT ROW AND UNBOUNDED FOLLOWING` calculates from the current match through the oldest match.
- `SUM()` calculates the cumulative total, while `AVG()` calculates the cumulative average.

**Note:** The SQL code above follows the exercise's stated requirement to calculate backward running values. The important correction from the originally supplied code is to order by `date DESC` and use `ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING`.
