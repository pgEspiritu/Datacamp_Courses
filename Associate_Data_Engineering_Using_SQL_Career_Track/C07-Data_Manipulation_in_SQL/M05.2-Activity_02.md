# 🏗️ Building on Subqueries in FROM

## 🎯 Objective

Use a subquery in the `FROM` clause to:

1. Combine information from the `match` and `country` tables.
2. Create a calculated `total_goals` column.
3. Use the prepared result as a temporary table.
4. Filter the final results for matches with **10 or more total goals**.

---

# 1. 🧠 The Main Concept

In the previous exercise, we used a subquery in `FROM` to filter matches before joining them to the `country` table.

This time, we will build a more complete subquery that:

- Gets the country name.
- Gets the match date.
- Gets home goals.
- Gets away goals.
- Calculates total goals.

The outer query then filters the prepared result.

### Mental Model

    match + country
          ↓
      Subquery
          ↓
    Add total_goals
          ↓
    Temporary table
          ↓
     Main query
          ↓
    Filter total_goals >= 10

---

# 2. 🔍 Build the Subquery

The subquery needs to select:

- Country name
- Match date
- Home goals
- Away goals
- Total goals

The structure is:

    SELECT
        name AS country,
        m.date,
        m.home_goal,
        m.away_goal,
        (m.home_goal + m.away_goal) AS total_goals
    FROM match AS m
    LEFT JOIN country AS c
        ON m.country_id = c.id

---

# 3. 🌍 Get the Country Name

The `match` table contains:

    country_id

But it does not contain the country name.

The `country` table contains:

    id
    name

So we join the tables:

    LEFT JOIN country AS c
        ON m.country_id = c.id

Then select:

    name AS country

This creates a column called:

    country

---

# 4. 📅 Select Match Information

The subquery also selects:

    m.date

    m.home_goal

    m.away_goal

These provide the date and the goals scored by each team.

---

# 5. ➕ Create `total_goals`

The subquery creates a calculated column:

    (m.home_goal + m.away_goal) AS total_goals

For example:

    home_goal = 6
    away_goal = 4

Then:

    total_goals = 6 + 4
                = 10

The calculated column is given the alias:

    total_goals

---

# 6. 🏗️ Complete Subquery

The complete subquery is:

    (
        SELECT
            name AS country,
            m.date,
            m.home_goal,
            m.away_goal,
            (m.home_goal + m.away_goal) AS total_goals
        FROM match AS m
        LEFT JOIN country AS c
            ON m.country_id = c.id
    ) AS subq

The alias is:

    subq

This is important because a subquery in the `FROM` clause needs an alias.

---

# 7. 📋 What Does the Subquery Produce?

Conceptually, the subquery creates a temporary table like:

| country | date | home_goal | away_goal | total_goals |
|---|---|---:|---:|---:|
| England | 2013-01-01 | 6 | 4 | 10 |
| Spain | 2013-02-15 | 8 | 2 | 10 |
| Germany | 2013-03-20 | 5 | 5 | 10 |
| France | 2013-04-10 | 3 | 1 | 4 |

The outer query can now treat this result as if it were a normal table.

---

# 8. 🔎 The Main Query

The outer query selects:

    SELECT
        country,
        date,
        home_goal,
        away_goal

Notice that the outer query does **not** need to write:

    subq.country
    subq.date
    subq.home_goal
    subq.away_goal

The reason is that the outer query is selecting directly from the subquery result.

The subquery is treated as a **single table**.

---

# 9. 🎯 Filter the Main Query

The calculated column:

    total_goals

was created inside the subquery.

The outer query can now use it:

    WHERE total_goals >= 10

This keeps only matches with at least 10 total goals.

---

# 10. 💻 Complete Query

    SELECT
        country,
        date,
        home_goal,
        away_goal
    FROM
        (
            SELECT
                name AS country,
                m.date,
                m.home_goal,
                m.away_goal,
                (m.home_goal + m.away_goal) AS total_goals
            FROM match AS m
            LEFT JOIN country AS c
                ON m.country_id = c.id
        ) AS subq
    WHERE total_goals >= 10;

---

# 11. 🔄 How the Query Works

The query has two levels.

## Level 1 — Subquery

    SELECT
        name AS country,
        m.date,
        m.home_goal,
        m.away_goal,
        (m.home_goal + m.away_goal) AS total_goals
    FROM match AS m
    LEFT JOIN country AS c
        ON m.country_id = c.id

This prepares the data.

It combines:

    match
      +
    country
      ↓
    Prepared table

---

## Level 2 — Main Query

    SELECT
        country,
        date,
        home_goal,
        away_goal
    FROM subquery
    WHERE total_goals >= 10

This uses the prepared data and filters it.

---

# 12. 🧠 Why Create `total_goals` in the Subquery?

Instead of repeatedly writing:

    home_goal + away_goal

we calculate it once:

    (m.home_goal + m.away_goal) AS total_goals

Then the outer query can simply use:

    WHERE total_goals >= 10

This makes the outer query easier to read.

---

# 13. ⭐ Important Concept: Subquery as a Table

This is one of the most important ideas in `FROM` subqueries.

Once you create:

    (
        SELECT ...
    ) AS subq

the outer query can treat `subq` like a normal table.

For example, if the subquery produces:

    country
    date
    home_goal
    away_goal
    total_goals

the outer query can use those columns just like columns from a regular table.

---

# 14. 🆚 Inner Query vs. Main Query

| Subquery | Main Query |
|---|---|
| Combines `match` and `country` | Uses the prepared result |
| Creates `total_goals` | Filters `total_goals` |
| Selects country name | Selects final columns |
| Performs the `LEFT JOIN` | Applies final filter |
| Prepares the data | Produces final result |

---

# 15. 🔑 Why No Table Alias in the Main Query?

The exercise specifically points out that the main query does not use the `subq.` prefix.

For example:

    SELECT
        country,
        date,
        home_goal,
        away_goal

This works because the outer query is querying the result of:

    ) AS subq

The subquery is treated as a table.

You could also explicitly use the alias:

    SELECT
        subq.country,
        subq.date,
        subq.home_goal,
        subq.away_goal
    FROM (...) AS subq
    WHERE subq.total_goals >= 10;

Both styles can work.

---

# 16. ⚠️ Important Difference from `WHERE` Subqueries

A subquery in `WHERE` is commonly used as a **condition**:

    WHERE team_api_id IN (
        SELECT hometeam_id
        FROM match
    )

A subquery in `FROM` creates a **table-like result**:

    FROM (
        SELECT ...
        FROM ...
    ) AS subq

### Think of them differently:

    WHERE subquery
        ↓
    Used for filtering

    FROM subquery
        ↓
    Used for preparing data

---

# 17. 📊 Example of the Filtering

Suppose the subquery produces:

| country | home_goal | away_goal | total_goals |
|---|---:|---:|---:|
| England | 6 | 4 | 10 |
| Spain | 8 | 2 | 10 |
| Germany | 5 | 5 | 10 |
| France | 3 | 1 | 4 |

The main query applies:

    WHERE total_goals >= 10

Result:

| country | home_goal | away_goal |
|---|---:|---:|
| England | 6 | 4 |
| Spain | 8 | 2 |
| Germany | 5 | 5 |

France is excluded because:

    3 + 1 = 4

and:

    4 < 10

---

# 🧠 Mental Model

Remember this as:

**JOIN → CALCULATE → PREPARE → FILTER**

    match
      +
    country
      ↓
    LEFT JOIN
      ↓
    Calculate:
    home_goal + away_goal
      ↓
    total_goals
      ↓
    FROM subquery
      ↓
    WHERE total_goals >= 10
      ↓
    Final results

# ⚡ Quick Reference

## Create a calculated column inside a subquery

    (home_goal + away_goal) AS total_goals

## Use a table inside a subquery

    FROM match AS m
    LEFT JOIN country AS c
        ON m.country_id = c.id

## Turn the subquery into a temporary table

    FROM (
        SELECT ...
    ) AS subq

## Filter the prepared result

    WHERE total_goals >= 10

---

# 🔑 Key Takeaways

- A `FROM` subquery can **combine and transform data** before the main query uses it.
- You can create calculated columns inside the subquery.
- `AS total_goals` gives a calculated expression a reusable column name.
- The outer query can filter the calculated column.
- A `FROM` subquery behaves like a temporary table.
- A `FROM` subquery must have an alias such as `AS subq`.
- The outer query can select columns from the subquery without repeating the original table aliases.
- This approach is useful when you need to **prepare data before filtering or analyzing it**.

> 🎯 **Core idea: Build the result you need inside the subquery, then treat that result like a table in the main query.**
