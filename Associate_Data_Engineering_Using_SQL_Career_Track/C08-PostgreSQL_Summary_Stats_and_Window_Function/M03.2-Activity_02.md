# Reigning Champions by Gender and Event

In the previous exercise, you used `PARTITION BY Gender` to ensure that men's and women's results were processed separately.

However, when working with multiple events, partitioning by gender alone is not enough. You also need to partition by event to prevent champions from different events from being compared with one another.

## Instructions

**100 XP**

- Return the previous champions of each year's events by gender and event.

## SQL Solution

```sql
WITH Athletics_Gold AS (
    SELECT DISTINCT
        Gender,
        Year,
        Event,
        Country
    FROM Summer_Medals
    WHERE
        Year >= 2000
        AND Discipline = 'Athletics'
        AND Event IN ('100M', '10000M')
        AND Medal = 'Gold'
)
SELECT
    Gender,
    Year,
    Event,
    Country AS Champion,
    -- Fetch the previous year's champion by gender and event
    LAG(Country) OVER (
        PARTITION BY Gender, Event
        ORDER BY Year ASC
    ) AS Last_Champion
FROM Athletics_Gold
ORDER BY Event ASC, Gender ASC, Year ASC;
```

## Explanation

- `WITH Athletics_Gold AS (...)` — Creates a Common Table Expression (CTE) containing the gold medal results for the selected athletics events.
- `SELECT DISTINCT Gender, Year, Event, Country` — Retrieves unique combinations of gender, year, event, and country.
- `Year >= 2000` — Includes Olympic results from 2000 onward.
- `Discipline = 'Athletics'` — Filters the dataset to athletics.
- `Event IN ('100M', '10000M')` — Selects the 100-meter and 10,000-meter events.
- `Medal = 'Gold'` — Retrieves only gold medal results.
- `Country AS Champion` — Renames the country column to `Champion`.
- `LAG(Country)` — Retrieves the champion from the previous row.
- `PARTITION BY Gender, Event` — Creates separate partitions for every gender-and-event combination.
- `ORDER BY Year ASC` inside `OVER()` — Arranges the records chronologically within each partition.
- `ORDER BY Event ASC, Gender ASC, Year ASC` — Controls the final display order.

## How PARTITION BY Works

The query creates separate partitions for each combination of gender and event.

| Gender | Event | Partition |
|---|---|---|
| Men | 100M | Men - 100M |
| Women | 100M | Women - 100M |
| Men | 10000M | Men - 10000M |
| Women | 10000M | Women - 10000M |

This ensures that `LAG()` retrieves the previous champion only from the same gender and event.

## Key Takeaway

When partitioning by multiple columns, SQL creates a separate partition for every unique combination of their values.

- `PARTITION BY Gender` — Separates men's and women's results.
- `PARTITION BY Gender, Event` — Separates results by both gender and event.
- `ORDER BY Year ASC` — Determines the chronological order within each partition.

**Remember:** If your analysis involves multiple grouping dimensions, include all relevant columns in `PARTITION BY` to prevent unrelated records from being compared.
